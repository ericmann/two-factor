# Two-Factor Secrets API (TOTP) build plan
Derived from docs/SPEC.md (Status: approved for build, unversioned) on 2026-09-28. SPEC.md wins over this file.

## Decisions
- Phases → SPEC defines none; derived as scaffold (test environment) → adapter and base hooks → TOTP integration → downgrade detection → WP-CLI → documentation. Each is a separate phase so the reviewer can check the storage contract before it is consumed.
- SPEC 4.6 assumes core's existing fallback covers a TOTP-only user whose provider is registered but unavailable → it does not (see Spec issues #1). P1-02 adds a generic base-class hook `Two_Factor_Provider::is_enrolled_but_unavailable_for_user( $user )` (default `false`) and teaches `Two_Factor_Core::get_available_providers_for_user()` to apply the existing `two_factor_fallback_provider_for_user` resolution when every enabled provider is either unavailable-and-enrolled or not registered. TOTP overrides it to `true` for affected users. No TOTP logic enters core.
- SPEC 4.5 per-user uninstall hook `uninstall_user_data( $user_id )` → implemented as a bulk static `Two_Factor_Provider::uninstall_user_data()` with no argument. Core cannot know which users carry a provider's marker without provider-specific logic, so the provider pages through its own users. Core calls it once per provider class before deleting user meta so the marker is still available for the lookup.
- Test seam for "API absent" (SPEC 5) → an `@internal` filter `two_factor_secrets_api_present` applied inside `Two_Factor_Secrets::is_api_present()`; it can only force `false`, never `true`. Hooks are reset by `WP_UnitTestCase` between tests, which is safer for an unattended run than a static the tests must remember to clear.
- Test seam for write failure and read-back mismatch → the Secrets API caches its provider and store in `static` locals for the whole PHP process (`_wp_secrets_get_provider()`, `_wp_secrets_get_store()`), so tests cannot swap a failing store in. `Two_Factor_Secrets` therefore routes its raw API calls through private wrappers that consult an `@internal` static `Two_Factor_Secrets::$test_overrides` (keys `set`, `get`, `delete`, `writable`, each a callable). It is not a hook and is documented as test-only. `Two_Factor_Secrets_UnitTestCase::tear_down()` clears it.
- Marker present, API present, network matches, but the API returns `null` → `WP_Error` code `two_factor_secret_missing` from `Two_Factor_Secrets::get_user_secret()`, not `null`. The marker asserts the secret exists, and SPEC goal 4 says an unreadable secret is never mistaken for "not configured". The profile UI's reset path clears the stale marker.
- Empty `$key` passed to `Two_Factor_Totp::set_user_totp_key()` → delegates to `delete_user_totp_key()` and returns its boolean. An empty secret is never written to the Secrets API.
- Site Health row not in SPEC's table (API present, `can_write()` false, plaintext remains) → `good`, with wording that migration is disabled by the `two_factor_use_secrets_api` filter or a read-only provider. Not nagging a deliberate opt-out matches the "do not nag" rule for the API-absent row.
- Affected-user detection when the API is present → only runs on multisite and only looks for markers naming a different network (`meta_compare => '!='`). A single site has one network, so no query runs there. Result cached in a site transient for `Two_Factor_Totp::AFFECTED_USERS_CACHE_TTL` (300 s).
- `wp two-factor secrets migrate` paging → ordered by ID, `number => batch`, `offset` advanced only by the number of users in the batch that were not migrated (failed or skipped), because migrated users drop out of the plaintext query. With `--dry-run` the offset advances by the full batch. Same approach for `export` over the marker query.
- `wp two-factor secrets export` when deleting the Secrets API entry fails after plaintext was verified → returns `true` (exported). The marker is always removed so precedence (SPEC 4.2 rule 1) is unambiguous; an orphaned ciphertext row is the same acceptable outcome SPEC 4.5 allows for uninstall.
- readme.md mirror (SPEC 6) → readme.md carries no FAQ, hooks or CLI sections (it defers to readme.txt), so no readme.md change is made; P5-01 states this in its commit body.
- Open questions in SPEC 8 → not resolved here by design; they go verbatim into `docs/PR-DESCRIPTION.md` (P5-03).
- Branch and PR target → SPEC 7 says the PR targets `master` on `ericmann/two-factor`. `docs/foundry.json` sets `baseBranch` to `feature/secrets-api-totp` because that is the branch these documents are committed on; the implementer's build branch is cut from it. The author retargets or merges by hand.

## Conventions
- Commit title `<ID>: <title>`; body with `Goal:`, `Tests:`, `Interpretation:` (any reading chosen where SPEC allowed two), `Measurement:` (tuning tasks only; none in this plan), `Manual check:`.
- Version placeholder for every new docblock: `@since 0.18.0`.
- Text domain for every string: `two-factor`. PHP 7.4 syntax only (no `match`, no union types, no `readonly`, no named arguments, no `str_contains`).
- Never modify anything under `includes/`.
- Never call `wp_*_secret()` / `wp_secrets_*()` outside `class-two-factor-secrets.php`. Always the `*_network_*` variants inside it.
- Canonical names used across tasks (restated in each task that needs them):
  - Adapter: `class-two-factor-secrets.php`, `class Two_Factor_Secrets` (all static). Slug for TOTP: `Two_Factor_Totp::SECRET_SLUG = 'totp'`. Secret name: `two-factor/{$slug}-{$user_id}`.
  - Marker: `Two_Factor_Totp::SECRET_NETWORK_META_KEY = '_two_factor_totp_key_network'`, value `(string) get_current_network_id()`.
  - Public filter: `two_factor_use_secrets_api( bool $use, int $user_id )`, default `true`.
  - Internal test filter: `two_factor_secrets_api_present( bool $present )`.
  - Internal test static: `Two_Factor_Secrets::$test_overrides` (array; keys `set`, `get`, `delete`, `writable`).
  - Actions: `two_factor_secrets_migrated( int $user_id, string $slug )`, `two_factor_secrets_migration_failed( int $user_id, string $slug, WP_Error $error )`, `two_factor_secret_unavailable( int $user_id, string $slug, WP_Error $error )`.
  - Error codes: `two_factor_secrets_api_missing`, `two_factor_secret_wrong_network`, `two_factor_secret_missing`, `two_factor_secrets_not_writable`, `two_factor_secrets_migration_mismatch`, `two_factor_secrets_export_mismatch`.
  - Base-class hooks: `Two_Factor_Provider::is_enrolled_but_unavailable_for_user( $user ): bool` (default `false`), `Two_Factor_Provider::uninstall_user_data(): void` (static, no-op).
  - Transient: `Two_Factor_Totp::AFFECTED_USERS_TRANSIENT = 'two_factor_totp_affected_users'`, TTL `Two_Factor_Totp::AFFECTED_USERS_CACHE_TTL = 300`.
  - Site Health test id: `two_factor_totp_secret_storage`.
  - CLI: `wp two-factor secrets <status|migrate|export>`; `Two_Factor_CLI_Command::SECRETS_DEFAULT_BATCH_SIZE = 100`.
  - Test base class: `Two_Factor_Secrets_UnitTestCase` in `tests/class-two-factor-secrets-test-case.php`, group `secrets`.
  - Deterministic test key: `WP_SECRETS_KEY` = `AQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQE=` (canonical base64 of 32 bytes of `0x01`).
- Every test that needs the real Secrets API calls `$this->require_secrets_api()` (marks skipped when `wp_get_network_secret()` does not exist). Every test that needs "API absent" calls `$this->simulate_api_absent()`.
- On multisite, every `get_users()` / `WP_User_Query` that looks for markers or plaintext keys passes `'blog_id' => 0`, otherwise the default capabilities meta filter hides users of other sites.
- Verification for every task: `npm run lint`, `composer lint-compat`, `npm test` (both suites, needs `npm run env start` once). Run the two suites sequentially, never concurrently.

## Phase 1 — Storage adapter and provider base hooks

### P1-01: `Two_Factor_Secrets` adapter with tests and the shared secrets test case
**Goal:** Add the static storage adapter that is the only place Two-Factor calls the Secrets API, plus the test base class every later secrets test extends.
**Files touched:** `class-two-factor-secrets.php` (new), `two-factor.php`, `phpstan.dist.neon`, `phpunit.xml.dist`, `phpunit-multisite.xml`, `tests/bootstrap.php`, `tests/class-two-factor-secrets-test-case.php` (new), `tests/class-two-factor-secrets.php` (new)
**Design constraints:** SPEC 4.1 (adapter surface and rules), 4.2 (marker semantics), 4.7 (`two_factor_use_secrets_api` docblock), 5 (seams). `two-factor.php` requires the file right after `class-two-factor-compat.php`. Add `class-two-factor-secrets.php` to `paths` in `phpstan.dist.neon` and to the coverage `<whitelist>` of both PHPUnit configs. Class `Two_Factor_Secrets`, every method `public static` unless stated:
- `is_api_present(): bool` — `function_exists()` for all six functions (`wp_get_network_secret`, `wp_set_network_secret`, `wp_delete_network_secret`, `wp_secrets_provider_is_writable`, `wp_secrets_provider_label`, `wp_secrets_memzero`) and `class_exists( 'WP_Secret' )`, evaluated at call time; result ANDed with `(bool) apply_filters( 'two_factor_secrets_api_present', true )`. Docblock marks the filter `@internal Test seam only; not a public extension point. Can only force false.`
- `is_provider_writable(): bool` — `false` when `! is_api_present()`; else `self::$test_overrides['writable']` when set, else `wp_secrets_provider_is_writable()`.
- `can_write( $user_id = 0 ): bool` — `is_api_present()` && `(bool) apply_filters( 'two_factor_use_secrets_api', true, (int) $user_id )` && `is_provider_writable()`. The filter docblock states that it controls writes and migration only, that already-migrated users are still read from the Secrets API while it is present, and that `$user_id` may be `0`.
- `get_secret_name( $user_id, $slug ): string` — `"two-factor/{$slug}-{$user_id}"`; `$slug` is validated with `/^[a-z0-9]([a-z0-9_-]*[a-z0-9])?$/`, throwing `InvalidArgumentException` otherwise.
- `get_marker_meta_key( $slug ): string` — `"_two_factor_{$slug}_key_network"` (for `totp` this equals `_two_factor_totp_key_network`; P2-01 asserts `Two_Factor_Totp::SECRET_NETWORK_META_KEY` matches).
- `get_user_secret( $user_id, $slug ): string|null|WP_Error` — read marker meta; `''`/`false` → `null` (no API call). Marker present: if `! is_api_present()` → `WP_Error( 'two_factor_secrets_api_missing' )`; if `(int) $marker !== get_current_network_id()` → `WP_Error( 'two_factor_secret_wrong_network' )`; else raw get: `WP_Error` → return it; `null` → `WP_Error( 'two_factor_secret_missing' )`; `WP_Secret` → `reveal()`; a `WP_Error` from `reveal()` is returned as is.
- `set_user_secret( $user_id, $slug, $value ): true|WP_Error` — requires `is_api_present()` (else `two_factor_secrets_api_missing`); raw set; on `WP_Error` return it without touching the marker; on success `update_user_meta( $user_id, marker, (string) get_current_network_id() )` and return `true`.
- `delete_user_secret( $user_id, $slug ): true|WP_Error` — if `is_api_present()` call raw delete and remember a `WP_Error`; always `delete_user_meta( $user_id, marker )`; return the remembered `WP_Error` or `true`. A missing secret is success.
- `provider_label(): string` — `wp_secrets_provider_label()` or `''` when absent.
- `memzero( &$value ): void` — `wp_secrets_memzero()` when it exists, else `$value = ''`.
- Private `api_set( $name, $value )`, `api_get( $name )`, `api_delete( $name )` — call `self::$test_overrides[ 'set'|'get'|'delete' ]` when set (`get` override returns `string|null|WP_Error` and is used in place of get-plus-reveal), else the `wp_*_network_secret()` function. `public static $test_overrides = array();` documented `@internal Test seam only; keys set, get, delete, writable.` No method logs, echoes or stores a revealed value anywhere except the return value.
The test base class `Two_Factor_Secrets_UnitTestCase extends WP_UnitTestCase` (abstract) provides: `require_secrets_api()` (markTestSkipped unless `function_exists( 'wp_get_network_secret' )`), `simulate_api_absent()` (`add_filter( 'two_factor_secrets_api_present', '__return_false' )`), `tear_down()` that sets `Two_Factor_Secrets::$test_overrides = array()`, deletes site transient `two_factor_totp_affected_users` and calls `parent::tear_down()`. `tests/bootstrap.php` requires it after the WP test library bootstrap (`WP_UnitTestCase` does not exist before that line).
**Acceptance tests:** `tests/class-two-factor-secrets.php`, class `Tests_Two_Factor_Secrets extends Two_Factor_Secrets_UnitTestCase`, `@group secrets`: `test_get_secret_name_format` (`two-factor/totp-42`, passes `wp_secrets_validate_name()` when available), `test_get_secret_name_rejects_invalid_slug`, `test_is_api_present_reflects_functions`, `test_is_api_present_internal_filter_forces_absent`, `test_can_write_true_with_api_present`, `test_can_write_false_when_api_absent`, `test_can_write_false_when_filter_opts_out` (asserts the filter receives the user ID), `test_can_write_false_when_provider_read_only` (`$test_overrides['writable']` returns `false`; `is_api_present()` stays true), `test_get_user_secret_null_without_marker`, `test_get_user_secret_round_trip_uses_network_scope` (after `set_user_secret`, `wp_get_network_secret( name )` finds it and `wp_get_secret( name )` returns `null`; marker equals current network ID), `test_get_user_secret_error_when_api_absent_with_marker` (code `two_factor_secrets_api_missing`), `test_get_user_secret_error_when_marker_names_other_network` (marker set to `get_current_network_id() + 1`, code `two_factor_secret_wrong_network`), `test_get_user_secret_error_when_marker_present_but_secret_gone` (delete via `wp_delete_network_secret` directly; code `two_factor_secret_missing`), `test_get_user_secret_passes_through_api_error` (`$test_overrides['get']` returns `WP_Error( 'secret_decryption_failed' )`), `test_set_user_secret_error_leaves_marker_absent` (`$test_overrides['set']` returns `WP_Error`), `test_delete_user_secret_removes_secret_and_marker`, `test_delete_user_secret_removes_marker_when_api_absent`, `test_delete_user_secret_missing_is_success`.
**Out of scope:** Any change to `Two_Factor_Totp`; the base-class hooks; readme or AGENTS.md text.
**Verification:** `npm run lint`; `composer lint-compat`; `npm test`; `npm run composer -- test -- --group secrets` runs the new class in both suites.

## Phase 2 — TOTP integration

### P2-01: TOTP tri-state read, Secrets API writes and lazy migration
**Goal:** Route `Two_Factor_Totp` key storage through the adapter with the 4.2 precedence, verified writes, and idempotent lazy migration, keeping every existing public signature.
**Files touched:** `providers/class-two-factor-totp.php`, `tests/providers/class-two-factor-totp-secrets.php` (new)

## Spec issues
1. **SPEC 4.6 relies on a fallback that does not exist.** `Two_Factor_Core::get_available_providers_for_user()` only forces the `two_factor_fallback_provider_for_user` provider when none of the user's stored providers is *registered*. A TOTP-only user whose provider is registered but reports `is_available_for_user() === false` currently yields an empty list, `get_primary_provider_for_user()` returns `null`, `is_user_using_two_factor()` returns `false`, and the password alone logs them in. Resolution: P1-02 adds the generic `is_enrolled_but_unavailable_for_user()` hook and the matching core branch; P2-02's regression tests prove the fail-closed behaviour SPEC asks for.
2. **`uninstall_user_data( $user_id )` cannot be driven by core without TOTP knowledge.** Resolved as a bulk static hook (see Decisions).
3. **Marker present but secret absent is unspecified.** Resolved as `WP_Error( 'two_factor_secret_missing' )` (see Decisions).
4. **Site Health table lacks the "API present, cannot write, plaintext remains" row.** Resolved as `good` with explanatory text (see Decisions).
5. **"Read-only provider" in the `can_write()` matrix has no Secrets API seam.** `wp_secrets_provider_is_writable()` reflects a provider that is cached per process; without a drop-in there is no way to flip it in-process. P1-01 covers it with the `writable` key of the adapter's `@internal` `$test_overrides`.
6. **SPEC 4.9 says PHPStan is level 5; AGENTS.md says level 2.** `phpstan.dist.neon` is level 5. P5-02 corrects AGENTS.md.
7. **Branch base.** SPEC 3 names base `master`; the plan documents are committed on `feature/secrets-api-totp` and `docs/foundry.json` uses that as `baseBranch`. The author retargets the final PR to `master` by hand.
8. **`readme.md` mirror.** No equivalent sections exist; nothing to mirror (Decisions).
9. **Test-only `WP_SECRETS_KEY` is public in `.wp-env.json`.** It only protects the throwaway test database and is deliberately deterministic per SPEC 5.
